## 目标与范围

为现有紫微网站增加同风格的奇门页面，支持九宫、复制、Markdown/PNG 导出与本地档案。用户确认首版采用**时家转盘·拆补法**，优先考察 GitHub 较受关注的排盘实现。星标用于选取调查对象，不作为准确性认证。

本轮使用 `xinghuo`，先读本项目 2026-10-17 的调研记录，再以 GitHub API、固定版本源码、可执行引擎和公开原始算例复核。因为问题是软件算法与集成，本轮集中 GitHub 及项目自身的公开算法文档；X、YouTube、小红书、知乎未尝试，不能视为已覆盖。没有调用 AI 解读服务，没有发送个人命盘资料。全部验算输入为公开例题或合成边界时刻。

检索词包括 `qimen`、`qimendunjia`、奇门排盘、值使中五宫起算。GitHub 搜索按星数降序；结果混有无关项目，因此以下是本轮筛出的相关候选，不是全网穷尽排行榜。

## 首版锁定口径

这组规则是本项目的明确计算约定；页面和导出需同时保留，不能只标一个笼统的“奇门盘”。

1. 输入为北京时间 UTC+08:00 的公历钟表时间，不做真太阳时修正。避免先转为浏览器本地时区的 `Date` 再取年月日。
2. 以实际交节时刻换节气；年柱按立春交节时刻，月柱按十二节交接。夏至起阴遁、冬至起阳遁。定局使用当时生效的二十四节气。
3. 日柱与拆补符头统一在 23:00 换日，时柱与之配套。农历日期仍描述输入的民用日期，不暗改输入时间或节气瞬间。
4. 三元由最近甲/己符头定：子午卯酉为上、寅申巳亥为中、辰戌丑未为下；不是交节后机械地每五天一元。对应六十甲子索引 `d`，符头为 `5 * floor(d / 5)`，元序为 `floor(d / 5) % 3`。
5. 地盘从局数宫起戊，按 `戊己庚辛壬癸丁丙乙` 在数字九宫阳顺阴逆排列。九宫数字顺序与外环 `1,8,3,4,9,2,7,6` 分开处理。
6. 中五固定寄坤二，天禽随天芮并携带地盘中五干。原始中宫信息独立保留；值符若为天禽，不直接改名为天芮。
7. 值符随时干；甲时用本旬所遁六仪。值使取旬首原宫的门，原宫为五则借死门，**从原始宫（包含五）起数**，阳顺阴逆数旬内时序；只有最终落五才寄二。不能先把起点五改二再计步。
8. 星、门维持各自固定外环相对顺序；八神为值符、腾蛇、太阴、六合、白虎、玄武、九地、九天，从值符实际宫阳顺阴逆。首版阳遁也不替换为勾陈、朱雀。
9. 基础盘只标时旬空和时马，分别保留空支与对应宫位。甲子旬戌亥均在乾六，不能算成两个不同空宫。

对中五计步的交叉依据：ocean `calculateEightDoors` 保留原始五起数；kinqimen `zhishi_pai` 同样先按数字宫飞布再解释门名；qimen-rs 的 [engine.rs](https://github.com/SpenserCai/qimen-rs/blob/c4e7fb140402245a3dc3409b362d6ccaad60755b/crates/qimen-core/src/engine.rs) 明确保留原宫并包含专用回归。公开产品的[规则说明](https://all1station.com/qimen)与[奇门解的值使说明](https://qimenjie.com/zh-Hant-TW/learn/chart-markers)也写明这一处理。后两者是其作者对自身排法的说明，不当作所有流派统一标准。

## 可集成路线与仍未验证的范围

首版采用小型 TypeScript 核心与现有历法依赖，依据上述锁定口径实现；以 MIT 项目作可复核算法参照，保留实际借鉴代码的许可证和归属。这样不会把 Python UI/AI 服务、3meta 的其他寄宫分支或全套断语一并引入。qimen-rs 本轮作为独立验证工具，不因此新增产品原生二进制依赖。

未核实范围：飞盘、置闰、茅山法、真太阳时、历史夏令时、任意全球时区、全部旺衰刑墓/暗干流派、占断有效性以及远期天文精度。此次确认的是所选取法的计算和可见基础盘，不是预测准确性的证明；可计算到某一年也不代表该年的交节时刻已获独立天文精度验证。

维护时应优先保留以上原始算例和实际交节/换日反例，再扩充有效日期、十二时辰、宫位完整性与时区无关性回归。若将来改变寄宫、八神或日界，应变更规则版本并让档案保留旧版本语义，不能把旧盘悄悄套用新规则。
