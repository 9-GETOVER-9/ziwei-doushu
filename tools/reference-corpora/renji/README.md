## 条目粒度说明（与天纪库的差异）

人纪判语是**逐行烧录字幕**级引文，平均 13 字/条；天纪库是段落级短引文，平均 141 字/条。

这个粒度为**逐句回放**而设计——点任一条直达该句所在的那一秒，适合跟读与字幕导播。
用于 RAG 检索时 13 字的 chunk 偏碎，建议改用按语义段聚合的
[`data/corpus-rag.md`](data/corpus-rag.md)，或按 `book + h2 + section` 自行合并。

## 数据是怎么保真的

| 机制 | 说明 |
|---|---|
| 双源交叉 | 烧录字幕 OCR 作主源 × whisper / FunASR 独立转写作探针；逐集一致率脚本自算，**不采信自报** |
| 七道门禁 | G1 去重 / G2 主源正确 + 探针覆盖≥95% / G3 一致率≥60% / G4 术语白名单 / G5 出处可回溯≥95% / G6 逐字命中≥90% / **G7 漏字率≤12%** |
| G7 漏字率 | 探针有语音而 OCR 未收录的字数占比。**G3 只衡量已收行准不准，衡量不到整段没抓到**——金匮18 曾 G3 71.7% 过关却丢了 24% 正文，故增设此道 |
| 源缺陷豁免 | 两集（金匮18、针灸40）经**抽帧目视实证**确认原片本身缺字幕，走 [`tools/g7_exemptions.json`](tools/g7_exemptions.json) 豁免，豁免后仍打印真实漏字率并在 L2 标注 |
| 只登记不改 | 产出方发现 OCR/ASR 错型只写进 `corrections-ledger.jsonl`，**不得改动主源**，由监督方逐条裁决 |
| 出处落点核验 | 每条判语的时间码须落在 OCR 行上，不得落在 ASR 补空行——全库 19,294 条 100% 通过 |
| 分刀零重叠 | 54 个抽取篇目之间出处零重复、段号零交叉、时间跨度不越界 |

## 快速开始

**人**：直接读 [docs/](docs/) 六部。

**AI / RAG**：

```python
import json
entries = [json.loads(l) for l in open("data/entries.jsonl", encoding="utf-8")]

# 按部 / 章目过滤
guizhi = [e for e in entries if e["book"] == "01-shanghan" and e["h2"] == "条12"]

def url(e):
    h, m, s = map(int, e["t_hms"].split(":"))
    return f"https://www.bilibili.com/video/{e['bvid']}?t={h*3600+m*60+s}"
```

**整包投喂**：[data/corpus-rag.md](data/corpus-rag.md)（约 25.7 万字）。

**跑门禁**：

```bash
python3 tools/gate_check.py --batch structured   # 结构层 G5/G6
python3 tools/gate_check.py --batch transcripts  # 转写层 G2/G3/G7
```

## 项目理念

**算法是公开的传统智慧，不应该被锁在围墙里。** 真正的价值在于解读的深度、
用户体验的打磨、以及持续运营的积累。

这份语料同样如此：倪师讲的话本就属于所有想学的人。我们做的是把它整理成
每句可回放、可溯源、可检索的形态，然后开源出来。
